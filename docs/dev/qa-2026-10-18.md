# 本地部署与测试记录（2026-10-18）

## 环境与运行产物

- Windows，Flutter 3.44.0 / Dart 3.12.0，构建使用 JDK 21。
- 项目专用 Android 35 x86_64 模拟器 `DontForget_API35`，设备 ID `emulator-5554`。
- Flutter SDK 位于忽略提交的 `build/tooling/.flutter/`；项目独立 Pub 缓存为 `.pub-cache/`，Gradle 缓存为 `build/tooling/gradle-home/`。
- 首次构建中修复了工具缺失、Gradle 下载中断、Maven TLS 连接失败及 NDK 安装不完整等环境问题。Gradle 镜像配置仅保存在本项目临时缓存，没有更改全局 Flutter 配置。
- 交付时，专用模拟器中的测试提醒、记录和测试密码已清除；正常 release 应用仍在运行，停留在中文首页。首次使用需设置自己的应急密码并完成权限配置。

本机若需要重新构建，可在项目根目录的 PowerShell 中设置当前进程环境：

```powershell
$taskRoot = (Get-Location).Path
$env:PATH = "$taskRoot\build\tooling\.flutter\bin;$env:PATH"
$env:GRADLE_USER_HOME = "$taskRoot\build\tooling\gradle-home"
$env:FLUTTER_STORAGE_BASE_URL = 'https://storage.flutter-io.cn'
$env:PUB_HOSTED_URL = 'https://pub.flutter-io.cn'
./scripts/Build-Android.ps1 -JdkPath 'D:\Develop\java\JDK21'
```

这些是当前机器临时工具链的路径；执行 `flutter clean` 会删除 `build/`，重新搭建环境时应使用独立安装的 Flutter SDK。

## 发现并修复的问题

| 问题 | 复现与影响 | 修复 |
| --- | --- | --- |
| 首次检出无法按脚本直接完成检查 | Gradle 启动器及 wrapper JAR 被忽略，构建脚本在 Flutter 生成这些文件前先调用 `gradlew.bat`，文件不存在 | 脚本先通过 Flutter 构建补齐 Gradle 启动器，再调用原生测试和 Lint；全部通过后才列出最终安装包 |
| 小屏大字号布局溢出 | 320 × 700 逻辑像素、英文、2 倍字号下，设置下拉框、首页筛选栏、提醒时间与任务标题出现横向溢出，部分内容被挤出屏幕 | 设置行与分区标题适时改为纵向布局；限制下拉框宽度；提醒时间和重复说明可换行；任务标题使用有限宽度 |
| 预览截图图标变成方框 | 预览测试写死 `D:/develop-app/flutter`，其他机器找不到 Material Icons 字体；这影响开发预览，不代表 APK 本身缺少图标 | 从当前 `FLUTTER_ROOT` 查找字体，并重新渲染核对 |
| 深色任务页状态栏对比不足 | 实际 release 截图中状态栏沿用浅色页面的深色图标，在深绿背景上难以辨认 | 任务页显式声明浅色系统栏图标，退出任务页后跟随原页面恢复 |
| 退格键缺少读屏标签 | 实际设备无障碍树中退格键可点击但没有名称 | 使用系统本地化的删除标签，并增加通过语义名称定位退格键、删除答案末位的交互回归测试 |

只在专用模拟器运行；测试会设置测试应急密码 `test-only-4729`，不应用于个人设备。运行方法见 [构建与分发](build-and-release.md)。

## 验证边界

- 测试数据渲染与模拟引擎的界面测试不能证明 Android 后台调度正常，分别记录结果。
- 模拟器的显示电源状态 Dozing 不等同于已经验收 Android 深度 Doze；本次后台熄屏复查通过，不替代长时间待机测试。
- 二维码值校验测试不等于真实相机识别测试。
- 三星 S20 真机的锁屏、Doze、省电策略、重启解锁前恢复，以及物理音量/振动和相机识别仍需真机验收。
- 当前 release 签名策略仍沿用项目既有 debug 签名自用流程。
- Lint 建议包括旧系统备份属性、可合并的 `v21`/`v26` 资源目录，以及使用 Kotlin KTX 扩展；未作为已复现的功能故障处理。
